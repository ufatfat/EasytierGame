# Windows、macOS 与全局协调服务

## 构建桌面端

需要 Node.js 24、pnpm 11、Rust stable 和当前平台的 Tauri 2 开发依赖（macOS 为 Xcode Command Line Tools；Windows 为 MSVC、Windows SDK、WebView2）。

```sh
pnpm install --frozen-lockfile --ignore-scripts
pnpm prepare:core
pnpm build
pnpm exec tauri build
```

内核默认固定为 EasyTier v2.6.4，通过 GitHub Release 元数据的 SHA-256 校验后安装。可用 `EASYTIER_VERSION` 更换版本。Windows x64、macOS Apple Silicon 与 Intel 分别在对应架构的机器构建。macOS 自动合并 `tauri.macos.conf.json`，产出 `.app` 和 `.dmg`。CI 将 `.app` 保留可执行权限打包为 zip，并产出 Windows 便携 zip；发布给其他用户前应使用自己的 Apple Developer ID 签名并公证。

Windows 保留原有管理员清单、计划任务自启及增强工具。macOS 启动带虚拟网卡的联机内核时，通过系统管理员授权启动；取消授权会显示启动失败，可重新尝试。停止该内核也会请求系统授权。纯中转服务器和 `--no-tun` 模式无需提升权限。

macOS 的配置、日志、下载内核和缓存保存在 `~/Library/Application Support/com.tauri.easytier-game/easytier/`，首次启动从 `.app` 的 Resources 复制缺少的资源，不覆盖用户配置。Windows 保留程序目录中的 `easytier/`。macOS 不提供 Windows 的开机计划任务、网卡跃点、ForceBindIP、防火墙和广播增强工具；虚拟网卡名称由系统分配。基础组网、成员列表、内核管理、配置管理、公告与固定 IP 登记共用逻辑。

## 运行全局协调服务

服务是独立的 Node.js 24 进程，使用内置 SQLite，无需安装第三方运行依赖。所有客户端连接同一服务，IP 和公告不按联机房间隔离。服务不会创建 EasyTier 中转节点，也不会改变网络名、网络密码或连接服务器。

服务不使用共享密钥：每位成员持有自己的个人访问密钥（`etk_` 开头），服务端只保存其 SHA-256。成员分为“成员”和“管理员”两种角色。

先启动服务：

```sh
IP_POOL='10.126.126.0/24' node service/server.mjs
```

Windows PowerShell：

```powershell
$env:IP_POOL = '10.126.126.0/24'
node service/server.mjs
```

可设置 `HOST`（默认 `127.0.0.1`）、`PORT`（默认 8787）、`DATABASE_PATH`（默认 `service/data/registry.sqlite`）、`CLAIMS_PER_MEMBER`（每位成员最多登记 IP 的设备数，默认 3）。生产环境在服务前配置 HTTPS 反向代理；客户端只允许 HTTPS 或本机回环 HTTP，不接受向其他地址的重定向。反向代理应添加请求速率限制。

### 创建第一个管理员

首次部署没有任何成员，在服务器上用同一个 `DATABASE_PATH` 运行：

```sh
node service/server.mjs member add <名字> --admin
```

命令会打印该管理员的访问密钥，只显示一次。其余成员由管理员在客户端“全局 IP / 公告 → 成员管理”中新建，也可以继续用命令行：

```sh
node service/server.mjs member add <名字>          # 新建成员
node service/server.mjs member list                # 列出成员
node service/server.mjs member reset-key <名字>    # 重新生成密钥，旧密钥立即失效
node service/server.mjs member revoke <名字>       # 吊销成员并释放其登记的 IP
```

命令行直接操作数据库，不需要密钥，也是管理员密钥丢失时的恢复手段。通过私密渠道把密钥发给本人。

### 管理员能做什么

- 新建成员并生成密钥、重置任意成员的密钥、在成员与管理员之间切换角色
- 吊销成员：密钥立即失效，其登记的 IP 被释放，已发布的公告保留（可单独删除），吊销后同名可重新创建
- 释放任意成员登记的 IP、删除任意公告

管理员不能修改自己的角色或吊销自己，避免误操作导致没有管理员；需要时由其他管理员或命令行处理。

所有客户端在主窗口点击底部“社区”，打开服务设置，填写服务地址和自己的个人访问密钥，点击“连接服务”。服务配置和客户端身份单独保存在本机，不加入房间配置分享和 config.json。公告和 IP 登记旁显示的成员名由管理员设定，主机名仍由客户端自填。

### 多地址与自动切换

“社区 → 服务设置”支持每行一个地址，最多 5 个。原有单地址配置无需重新填写；保存新设置后保留地址顺序，自动去重。所有地址共用同一把个人密钥和设备身份。

先按配置顺序尝试，成功后优先复用最近成功的地址；该地址连接失败时再尝试其他地址。社区状态栏显示当前地址和是否使用备用地址，大厅也显示当前连接的地址。社区在出错后继续定时刷新，网络恢复后可以重新连接。每个地址的连接超时为 3 秒，完整请求超时为 8 秒；一次请求最多尝试每个地址一遍。

- 读取遇到连接失败、响应中断、无效响应或 HTTP 5xx/408 时自动尝试备用地址。
- 已确认未发送的写入（如 TCP 连接被拒绝）可以切换地址后提交。
- 写入超时、响应中断或 5xx 无法证明服务端未执行时，不自动重复提交。客户端通过只读请求恢复备用连接，并提示“操作结果未确认”，需要刷新检查。这避免公告重复发布或重复重置一次性密钥。
- 密钥失效、权限不足、IP 冲突和其他业务错误直接显示，不通过切换地址绕过。

**备用地址须连接同一套协调服务数据**，例如同一个服务实例的多个反向代理入口。客户端不复制 SQLite 数据，也不把独立数据库合并成高可用集群；不同数据源会导致 IP、房间和成员状态不一致。HTTPS 校验和禁止自动重定向的限制对每个地址分别生效。

## 固定 IP 登记

1. 填写主机名，连接协调服务。
2. 在固定 IP 页输入网段内的地址，点击“登记 IP”，确认“用于联机”开关已开启。
3. 下次启动或重新联机时，客户端会重新向协调服务确认登记，向 EasyTier 传入 `--ipv4 IP/前缀`，不传 DHCP 参数。
4. 停止联机后可变更登记或释放；同一个地址只允许一个客户端登记，同一客户端只保留一个地址，每位成员最多为 `CLAIMS_PER_MEMBER` 台设备登记。一台设备的登记归属于登记它的成员，换用其他成员的密钥不能接管，需要管理员先释放。变更冲突会保留原地址。

预约不会因客户端离线或服务重启释放。登记模式下协调服务不可达会阻止启动，避免误用过期地址；可在界面主动关闭登记模式恢复手动或 DHCP 配置。使用外部 TOML 启动时需要关闭登记模式，避免误以为登记 IP 已应用。

登记只能协调使用该服务的客户端，无法阻止其他 EasyTier 软件手动配置重复 IP 或 DHCP 占用该地址。需要所有联机成员统一使用登记模式，并选择不与现有局域网冲突的网段。全局唯一的 IP 也不等于客户端位于同一个 EasyTier 网络，双方仍需要正确的组网配置。

身份分两层：个人访问密钥代表“谁”，决定公告和登记归属哪位成员；本机随机 256 位设备令牌代表“哪台设备”，用于区分同一成员的多台设备的 IP 登记，服务只保存它的 SHA-256 标识。请勿复制整份本地存储到另一台客户端，否则两台会共享设备身份。清除应用数据后重新填写同一把密钥即可恢复成员身份，原设备的 IP 登记可由管理员释放。数据库和 `-wal` 文件应使用一致性备份；恢复数据库不会恢复客户端的本地身份令牌。

## 公告

每台客户端可发布纯文本标题和内容，所有已连接客户端共享。列表展示最新 100 条，每个客户端最多保留 100 条；发布者可撤回自己的公告，可勾选“仅看本机发布的公告”管理自己的全部保留公告。窗口打开时每 15 秒刷新，也可手动刷新。失败时显示错误和上次成功更新时间，保留已有数据。内容按文本渲染，不执行 HTML。

## 房间大厅

所有连接同一协调服务的成员共享大厅。先在主窗口成功联机，再到“大厅”发布；服务器、房间名取自当前联机配置，使用外部 TOML 时不能发布。每位成员同时最多发布一个房间。

- 默认使用“向房主索取密码”：服务既不存储也不返回密码。加入者在确认弹窗临时输入。
- 选择“公开密码”后，服务保存密码；列表、发布、编辑接口均不返回密码，仅经过成员认证的房间连接接口返回。
- 加入会先停止当前联机，再只替换服务器、协议、房间名和密码；保留成员名、手动/DHCP/全局登记模式及其他设置。服务器与协议保持原始配对。
- 客户端每 30 秒上报人数和心跳；90 秒无心跳后房间从查询结果移除。默认停止联机自动下架，可在发布时关闭；即使关闭，心跳到期仍会下架。
- 房主可以编辑展示信息、人数上限及下架选项；服务器、房间名、密码需要下架后重新发布。管理员可下架任何房间，不能编辑别人的房间。
- 满员时禁止加入，可选满员后隐藏。人数由房主客户端周期上报，加入不预占座位。
- 预计延迟由客户端测量到服务器的 TCP 连接耗时，包含 DNS；UDP 等无法测量的连接显示未知。该值不代表玩家间的游戏延迟。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `/v1/rooms` | 浏览 / 发布，GET 支持 `game`、`has_slot` |
| PATCH / DELETE | `/v1/rooms/:id` | 房主编辑 / 房主或管理员下架 |
| PUT | `/v1/rooms/:id/heartbeat` | 发布设备续期并上报人数 |
| GET | `/v1/rooms/:id/connection` | 取得加入配置，满员时拒绝普通加入者 |

标题最多 24 字、说明 200 字、标签最多 5 个，每个标签最多 12 字；人数上限 1–256。房间保存在现有 SQLite 数据库，启动时自动创建表，无需手动迁移。吊销成员会清理其房间并释放其 IP，公告保留。

## 新界面

主窗口为 400×720，面板为 600×720；底部包含大厅、房间、游戏库、社区、高级、日志，Windows 额外显示工具。主按钮固定在底部，窗口缩小时内容区滚动。主题菜单支持跟随系统、浅色、深色。高级设置有六个分类和搜索；日志支持级别、关键词和自动跟随。

Windows 工具按广播、跃点、防火墙、Ping、ForceBindIP 排列。广播开关使用 EasyTier 自带的 UDP 广播中继；原项目注释掉的 WinIPBroadcast 不启动。高级设置和广播开关在下次联机时生效。

## 按平台显示窗口标题栏

macOS 的主窗口在 Rust 创建前启用原生窗口装饰，动态面板通过统一窗口入口使用相同设置：`decorations: true`、`titleBarStyle: overlay`、隐藏系统标题文字并保留原生红黄绿按钮。页面为左侧按钮预留 92px，移除重复的自绘最小化/关闭按钮，窗口按钮与应用主题同步。公共服务器和子网代理页也提供对应的标题区域。红色按钮仍遵循现有关闭逻辑：主窗口隐藏到托盘，功能面板关闭；黄色和绿色按钮交由系统处理。

Windows 继续使用现有无边框自绘标题栏、右侧主窗口按钮和面板关闭按钮。浏览器预览保留可操作的自绘按钮。macOS 的主窗口及动态面板继续开启 `acceptFirstMouse`。

实现依据：[Tauri 窗口标题栏配置](https://v2.tauri.app/reference/config/#titlebarstyle)。Mac 专属初始化采用编译条件，不覆盖 Windows 配置。
